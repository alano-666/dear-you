# 无聊天框陪伴 AI — 产品头脑风暴输出

> 日期:2026-09-11 | 阶段一:发散 → 概念 | Skill: `pm-product-discovery:brainstorm-ideas-new`

## 1. 机会确认(Opportunity)

**产品概念**:一款没有聊天框的陪伴型 AI。用户主动提交照片/视频/文字片段 → 形成个人时间线 → AI 持续观察、记忆、理解用户生活状态 → 主动发现变化与关联 → 以周/季/年为周期生成"写给你的信"。

**早期目标人群假设**(阶段二验证):25-35 岁、有记录愿望但坚持不了日记的智能手机一代;延伸:独居年轻人、异地恋情侣、新父母。

**用户想达成的结果**:
- 生活被整理成叙事,而非散落的相册
- 感到"被看见、被记住"(不是被评判)
- 回望时发现意义与变化
- 无需社交压力的倾诉出口

**核心循环假设**:
```
低摩擦提交素材 → AI 积累时间线 → AI 发现变化/关联
        ↑                                    ↓
   回应即投喂(纠错/补充/追问) ← 周期信件送达(周/季/年)
```

**必须坚守的产品约束**:
1. 没有聊天框(这是定位,不是缺失)
2. 素材以用户主动提交为主(不是全自动监控——隐私与心智的底线)
3. 周期信件是内容载体,不是 feed

> ✏️ **2026-09-11 修订**:信件周期新增"每天一封日信 + 每周一封周信"(demo 版核心节奏),原愿景的季信/年信延后至正式版。

## 2. 三角色头脑风暴(15 条)

### PM 视角(市场契合 / 价值 / 差异化)

**P1. 多渠道信件送达** — 信是产品本体:App 内 + 微信服务号 + 邮件 + 实体打印版可选。日记 App 要你打开它,陪伴 AI 来找你。实体版 = 付费点 + 送礼传播。

**P2. 信件内的轻回应机制("回应即投喂")** — 五种结构化回应替代聊天框:① 情绪贴纸(被戳中/暖心/想哭)② "多讲点"(AI 展开)③ "你记错了"(纠错——信任功能,也是 AI 的对齐信号)④ 补一张图(回应变成新素材)⑤ 封存(时间胶囊)。闭合循环同时守住"无聊天框"范式。

**P3. "变化雷达"——三类主动发现** — 把"发现变化"具体化:① 对比(与过去的你)② 回响(你提过的愿望、旧素材自我呼应)③ 缺失(你不再做的事)。周期性触发,生日/纪念日特辑。

**P4. 年度实体书/时间胶囊** — 年信升级为可下单实体画册:情感峰值 + 付费点 + 送礼传播(growth loop)。

**P5. 多人共同时间线("给你们俩的信")** — 情侣/家人/挚友共建一条时间线,季信写给关系本身。网络效应提高留存,但隐私复杂度高,后置。

### 设计师视角(体验 / 引导 / 参与)

**D1. 零压力提交入口** — 桌面 widget 一键拍照/语音、Siri 捷径、锁屏小组件;首屏 = 提交入口 + 时间线,不是聊天框。

**D2. "河流"视觉语言** — 素材是水滴/光点,信件是河畔驿站;强调"被珍藏"而非"被存储";时间线可漫游回望。

**D3. "等信"的仪式感** — 专属信鸽通知、逐字浮现(typewriter)的阅读体验、spotlight 模式(只显示信中引用的素材)、读完可"折起"。

**D4. 渐进式 onboarding——"交给 AI 的第一件东西"** — 没有注册表单,第一步交出一张照片/一段文字,AI 立刻回第一封"欢迎信"。用产品本身教学"交东西 → 收到理解"的心智,第一天建立。

**D5. 情感化回望交互** — 触摸素材 → AI 讲述当时的故事;"给三个月后的自己"时间胶囊;素材与信件双向链接(从信跳回素材,从素材看它被哪封信引用过)。

### 工程师视角(技术创新 / API / 平台)

**E1. 多模态记忆引擎(Life Memory Graph)** — CLIP 视觉向量 + 语音转写 + OCR;构建"实体-时间-情感"知识图谱(人/地点/活动/情绪)。让"发现变化"是图谱查询而非自由生成——可信度的技术底座。

**E2. 隐私优先采集管线** — 端侧(on-device)人脸/场景聚类,敏感数据本地处理,仅摘要/向量上云;端到端加密;"遗忘"接口(删除素材 + 撤销相关记忆);全量数据导出。隐私是品类生死线,不是功能。

**E3. 信件生成双模型架构** — 周信 = 轻量模型 + RAG 检索;季/年信 = 长上下文"全文读档" + 叙事规划。事实核查层:信中每句话引用素材来源,可点击跳转——解决"AI 说错你的生活"的信任问题。

**E4. 主动发现引擎(Change Detection / Serendipity Engine)** — 定时任务对比时间窗口(本周 vs 上周、今年 vs 去年),检测:习惯漂移、新面孔/地点、情绪趋势、未完成愿望;产出"发现候选"交给信件生成器。产品灵魂的技术实现。

**E5. 温和的平台集成(可选)** — HealthKit 步数/睡眠、低频位置签到、相册自动补充,提高时间线密度;但必须"可选 + 明确授权",不破坏"主动交"的心智。

## 3. Top 5 优先想法(按 核心价值 × 验证速度 × 差异化 加权)

### 🥇 1. 发现引擎 + 变化雷达(E4 + P3)

**入选理由**: "主动发现变化与关联"是整个产品 vs 日记 App 和聊天 AI 的唯一定位差。没有它,产品退回"带 AI 的相册"。

**待验证假设**:
- 用户对 AI 的"发现"感到惊喜而非冒犯(隐私冒犯风险真实存在)
- 对比/回响/缺失三类能覆盖用户真正在意的变化
- 一次幻觉式错误发现会严重伤害信任 → 必须可追溯

**最便宜的验证**: 招募 10 人授权旧相册 → 生成 30 条"发现" → 测 wow 率 / 尴尬率 / 继续使用意愿。成本≈0,2 周内出结论。

### 🥈 2. 首封"欢迎信" onboarding(D4)

**入选理由**: 没有聊天框 = 没有对话式教学,onboarding 必须用产品本身完成;第一天建立"交东西 → 收到理解"的心智是留存第一杠杆。

**待验证假设**: ① 用户愿意在第一分钟交出真实素材 ② 首封信能产生"被理解"的感受 ③ 首封信体验驱动 Day-7 留存

**最便宜的验证**: Figma 交互原型 + 真实 LLM 后端,10 人可用性测试,测"交出素材"完成率与情绪反馈。

### 🥉 3. 信件内轻回应机制(P2)

**入选理由**: 没有输入框,表达欲需要出口;回应同时是 AI 的对齐信号(纠错/追问),产品顺手完成了 RLHF 数据闭环。

**待验证假设**: ① 五种回应(贴纸/多讲点/纠错/补图/封存)覆盖需求 ② 用户会主动纠错而非沉默离开 ③ 纠错率可作信任健康度指标

**最便宜的验证**: 周信 demo 后跟踪回应率分布;访谈问题"如果 AI 写错了你的生活,你会怎么做?"

### 4. 多渠道信件送达(P1)

**入选理由**: "产品来到你面前"是品类级差异;中国场景微信服务号是低摩擦渠道;实体信是情感峰值 + 付费点。

**待验证假设**: ① 站外信打开率 ≥ App 推送 ② 用户不反感被"找到"(频控是关键,过度推送是死亡) ③ 实体打印意愿存在

**最便宜的验证**: 2 周 A/B——同一封周信,App 内 vs 微信/邮件送达,测打开率 + 后续提交行为;实体版做小范围预购测试。

### 5. 零压力提交入口(D1)

**入选理由**: 没有素材就没有一切——供给侧生死线;widget/快捷指令把提交成本降到 2 秒。

**待验证假设**: ① 提交摩擦(而非动力)是放弃记录的主因 ② widget 提交显著提升周频次 ③ 河流隐喻 vs 传统时间轴的留存差异

**最便宜的验证**: 2 周行为实验——iOS 快捷指令 + 相册自动导入 vs 手动提交,对比频次。

> ⚠️ **2026-09-11 修订(2 天 demo 限制)**:Top 5 全部进入 demo——其中 ① 识别+留存记忆(含欢迎信)② 日信/周信 ③ 河流 为**真实现**(真调 AI);其余为轻量演示版。完整裁决见第 6 节。

## 6. 2 天 Demo 范围(2026-09-11 修订 v3)

### 已确认的决策

| 决策 | 选择 |
|---|---|
| 运行方式 | Vercel 部署上线 + 本地 `npm run dev` 保底(评委在国内时 vercel.app 可能不稳) |
| 视频处理 | 浏览器端抽帧(1-3 帧)后识别,不装 ffmpeg |
| AI 服务 | 智谱 GLM:GLM-4V 系列识别照片/视频帧,GLM 系列生成信件(模型名以官方文档为准);接口写成**模型可切换**抽象层(OpenAI 兼容) |
| 记忆存储 | 浏览器 localStorage(照片压缩成缩略图),零后端存储零配置;每次生成信件时把全部记忆发给 AI |

### Demo 范围裁决:三个"真实现" + 其余轻量

**✅ 真实现(真调 AI):**

| 功能 | 实现方式 |
|---|---|
| ① 识别 + 留存记忆 | 照片 → 客户端压缩 → GLM-4V 识别(描述/标签/情绪);文字 → 直接入库(AI 提取情绪标签);视频 → 浏览器抽 3 帧 → 逐帧识别合并。全部存为"记忆条目"进时间线 |
| ② 每天/每周回信 | "日信"(最近 24h 记忆)与"周信"(近 7 天 + 对比/回响/缺失三类发现)两个生成入口;第一次提交后自动生成首封欢迎信 |
| ③ 河流视图 | 记忆条目按时间垂直流动展示,新提交素材有流入动画 |

**⚠️ 轻量演示版(不真做):**

| 功能 | 轻量方式 |
|---|---|
| 轻回应贴纸 | 三个贴纸(被戳中了/多讲点/你记错了)+ 预置反馈文本,纯前端 |
| 多渠道送达 | 微信卡片/邮件版式/实体信封面三个纯 CSS 静态预览 |
| 零压力提交 | 首屏大按钮 + 拍照/文字/视频三入口;不做真 widget/捷径 |

**❌ 不做**:登录、隐私加密、真实微信/邮件集成、季信/年信、多人时间线。

### Demo 剧本(现场 3-5 分钟)

1. **开场**:首屏不是聊天框,是"今天,有什么想交给我的?"+ 三个提交入口
2. **提交**:现场拍一张照片(或传一段文字)→ 显示"AI 正在看……" → 生成记忆条目流入河流
3. **河流**:滚动展示预置 + 刚提交的记忆,证明"留存"
4. **日信**:点开"今天的信"→ 逐字浮现 → 引用刚才交的照片 → 高亮"发现"(对比/回响/缺失)
5. **周信**:切换"本周的信"→ 展示 7 天回顾与变化
6. **回应**:点贴纸"被戳中了" → 温柔反馈
7. **多渠道**:展示微信卡片/邮件/实体信三种送达样式(概念)
8. **收尾**:"明天见"——强化陪伴与日/周节奏

### 技术方案

- **栈**:Next.js(App Router)全栈:前端页面 + `/api/recognize`(识别)+ `/api/letter`(生成信件)
- **AI 抽象层**:一个 `lib/llm.ts` 统一封装(chat + vision),内部用智谱 OpenAI 兼容接口;以后换 Claude 只改这一个文件
- **存储**:localStorage —— 记忆条目数组 + 照片缩略图(客户端 canvas 压缩);提供"导出记忆 JSON"按钮
- **视频抽帧**:`<video>` + `<canvas>` 浏览器端抽 3 帧,逐帧调识别 API
- **信件渲染**:逐字浮现(typewriter)是仪式感核心;信中引用记忆的 id,前端高亮并点击跳回河流
- **保底方案**:内置一封预生成的"备用周信",现场 API 失败时无缝切换(标注演示数据)

### Demo 之后

Demo 本身就是阶段二的第一个"实验":现场反应 = 发现引擎 wow 率的初版数据。观察两件事:

- 观众问"这是真的 AI 吗?"→ 体验成立
- 观众开始分享自己的故事,而不是问功能细节 → 情感共鸣成立

之后回到正式 PM 流程:访谈提纲 + 假设验证。
