## 1. Summary

《致你》(英文名 Dear You)是一款没有聊天框的陪伴型 AI。用户把生活中的照片、视频、文字交给它,它把素材变成一条会流动的个人时间线("河流"),并每天、每周给用户写一封"写给你的信",讲述它看到的生活与变化。

本文档定义 **2 天内完成、用于现场 3-5 分钟演示的 Demo 版**:哪些功能真做(真调 AI)、哪些轻量展示、哪些不做,以及技术方案与验收标准。

## 3. Background

**为什么做**:现在市面上的 AI 陪伴产品(Replika、星野等)都是"聊天框"形态——用户必须主动找话说,AI 被动回应。但人真正渴望的陪伴感,是"有人记得你的生活"。日记 App(心光、Day One)能记录,却不会"回信"。

**为什么是现在**:能看懂照片的多模态模型已经便宜到免费(智谱 glm-4v-flash 实测免费可用),让"AI 持续观察生活"第一次有了技术可能。生成一封好信的成本低到可以忽略。

**这个 Demo 要证明什么**:一句话——**用户愿不愿意"把生活交给 AI,然后等一封信"**。如果评委看完 demo 开始分享自己的生活,而不是问功能细节,我们就赢了。

---

## 4. Objective

**目标**:2 天内做出一个现场 3-5 分钟的 Demo,证明"交素材 → 河流 → 收到一封懂你的信"这个循环成立且动人。

**Key Results(验收标准)**:

1. **KR1**:现场能完整走通一次演示:提交照片 → AI 识别 → 流入河流 → 生成日信 → 信中引用这张照片,并给出至少 1 条"发现"
2. **KR2**:信件质量达标——评委中至少 1 人主动说"想用"或分享自己的生活故事(定性)
3. **KR3**:全程无事故——API 失败时有备用周信兜底;断网时本地版本可运行
4. **KR4**:观众 30 秒内看懂"这不是一个聊天 App"(无聊天框心智传达成功)

**与战略对齐**:这是产品愿景(数字伙伴)的最小可行证明;同时是头脑风暴文档 Top 1 假设("用户对 AI 的发现感到惊喜")的第一次真实测试——现场反应就是验证数据。

## 5. Market Segment(s)

**本 Demo 的直接观众**:黑客松评委与现场观众(不是真实用户)。因此体验要求:**30 秒看懂、3 分钟被打动**。

**Demo 代表的真实用户**(正式版再验证,暂不投入研发):25-35 岁想记录生活但坚持不了日记的人;独居青年;异地恋情侣。

**约束**:
- 评委没有耐心读说明文字,产品必须"自己会说话"
- 现场网络可能不稳 → 必须有断网/API 失败兜底
- 演示设备是手机竖屏(PC 上用手机尺寸的竖屏容器展示)

---

## 6. Value Proposition(s)

**用户"雇佣"这个产品做什么(Jobs to be done)**:

1. **帮我记住我的生活**——不用整理、不用写日记,随手交出素材就行
2. **告诉我,我的生活正在发生什么**——自己看不见的变化(习惯、情绪、未完成的愿望),有人替我看见
3. **陪我回望**——在每天、每周的节点,有人用一封信把我的日子讲回给我听

**相比竞品赢在哪**:

| 竞品 | 它们的做法 | 我们的不同 |
|---|---|---|
| 日记 App(心光、Day One) | 要你自己打开、自己写 | 交出去就行,而且有"回信" |
| AI 聊天陪伴(Replika、星野) | 你必须找话说,它被动回应 | 它主动来;它有真实记忆库,记得你交过的每样东西 |
| 相册"回忆"(Apple/Google) | 把老照片翻出来播放 | 我们不只是回放,是"理解"之后写成信 |

## 7. Solution

### 7.1 UX / 用户流程(Demo 剧本)

Demo 共 4 个界面,8 步走完:

```
[首页·提交] → [河流·时间线] → [信件·读信] → [送达·概念预览]
```

| 步骤 | 界面 | 动作与文案 | 动效与细节 |
|---|---|---|---|
| 1 开场 | 首页 | 顶部问候:"今天,有什么想交给我的?" 下方三个大入口:📷 拍张照片 / ✍️ 写几句话 / 🎬 传段视频 | 首屏**没有输入框**(核心心智);入口大而醒目 |
| 2 提交 | 首页 | 现场拍一张照片(或输入一段文字)→ 点击"交给它" | 提交后显示"AI 正在看……"(2-4 秒,识别中状态) |
| 3 入河 | 河流页 | 识别完成 → 新记忆条目从底部**流入河流** | 流入动画;条目卡片:缩略图 + AI 一句话描述 + 时间 |
| 4 留存 | 河流页 | 向上滚动,展示预置的"过去 30 天"15-20 条记忆(照片/文字混合) | 证明"它都记得";点击任意条目可展开 AI 的描述与情绪标签 |
| 5 日信 | 信件页 | 点开"今天的信"→ 逐字浮现 | 信中引用刚才交的照片(高亮,可点击跳回河流);含"发现"区块,至少 1 条 |
| 6 周信 | 信件页 | 切换到"本周的信" | 7 天回顾;三类"发现"(对比/回响/缺失)各至少 1 条 |
| 7 回应 | 信件页 | 点贴纸"被戳中了" | 温柔反馈一句(预置文本) |
| 8 送达+收尾 | 送达页 | 展示这封信的三种送达样式:微信卡片 / 邮件 / 实体信封面 | 概念预览,静态切换;最后一屏:"明天见" |

**关键体验原则**:① 全程无输入框、无"发送"按钮的对话感;② 每步之间 AI 都在场(识别中/正在写信),但不能让等待超过 5 秒;③ 信件是主角,UI 不抢戏。

### 7.2 Key Features(功能清单与验收标准)

**✅ 真实现(真调 AI)——必须全部通过验收:**

| ID | 功能 | 说明 | 验收标准(AC) |
|---|---|---|---|
| F1 | 照片识别 | 上传照片 → 客户端压缩(最长边≤1024px)→ 调 glm-4v-flash → 返回 {描述, 标签, 情绪} → 存为记忆条目 | 提交一张真实照片,3 秒内出现描述;描述准确(不含幻觉);条目进入记忆库 |
| F2 | 文字提交 | 输入一段文字直接入库;AI 提取情绪标签(可选,失败不阻塞) | 输入文字 → 立刻流入河流;刷新页面后仍在(留存验证) |
| F3 | 视频识别 | 浏览器 `<video>`+`<canvas>` 抽 3 帧(首/中/尾)→ 逐帧调 glm-4v-flash → 合并为一条记忆(附第 1 帧缩略图) | 传一段短视频 → 生成一条记忆,描述能反映视频大意;抽帧在浏览器完成,不装 ffmpeg |
| F4 | 记忆库 | localStorage 存储;条目结构见 7.3;照片存压缩缩略图;提供"导出记忆 JSON"按钮 | 所有条目刷新后仍在;导出按钮能下载完整 JSON |
| F5 | 河流视图 | 记忆条目按时间垂直排列;新条目流入动画;点击条目展开 AI 描述、标签、情绪 | 15-20 条预置 + 现场提交的条目全部可见;滚动流畅;动画不卡顿 |
| F6 | 日信 | 把全部记忆(重点最近 24h)发给百智云生成"今天的信";信中引用记忆用 `[[id]]` 标记,前端渲染为高亮可跳转 | 生成成功;至少引用 1 条记忆;含"发现"区块;引用点击可跳回河流对应条目 |
| F7 | 周信 | 近 7 天记忆;要求三类发现(对比/回响/缺失)各 ≥1 条 | 三类发现全部出现;每类至少 1 条可点击引用 |
| F8 | 欢迎信 | 记忆库为空时首次提交后自动生成第一封信(欢迎 + 约定:每天/每周给你写信) | 首次提交后自动触发;文案建立"交东西 → 收到理解"的心智 |
| F9 | 信件页 | 逐字浮现(typewriter)渲染;引用高亮;发现区块视觉区分;日信/周信切换 | 逐字浮现速度可读(约 20-40 字/秒);切换流畅 |
| F10 | 备用周信 | 内置一封预生成周信;API 失败时自动切换并标注"演示数据" | 断网状态下周信仍可展示,演示不中断 |

**⚠️ 轻量演示版(不真做,验收=存在且不抢戏):**

| ID | 功能 | 说明 |
|---|---|---|
| F11 | 贴纸回应 | 三个贴纸(被戳中了/多讲点/你记错了)+ 预置反馈文本,纯前端切换 |
| F12 | 多渠道预览 | 微信卡片 / 邮件版式 / 实体信封面,三个纯 CSS 静态样式,从信件页底部进入 |

**❌ 不做(明确排除,防范围蔓延)**:登录与用户系统、隐私加密、真实微信/邮件集成、季信/年信、多人时间线、真实 widget/快捷指令、服务端数据库。

### 7.3 Technology(技术方案)

**架构**:

```
浏览器(手机竖屏)
  ├─ 前端页面:首页提交 / 河流 / 信件 / 送达预览
  ├─ localStorage:记忆库(条目 + 照片缩略图)
  └─ API 调用 → Next.js API Routes
                    ├─ POST /api/recognize  照片/视频帧识别
                    └─ POST /api/letter     生成日信/周信
                          └─ lib/llm.ts(模型可切换抽象层)
                                ├─ 视觉:智谱 glm-4v-flash(免费,✅ 2026-09-11 实测连通)
                                └─ 文本:百智云网关 glm-5.3-flash(✅ 实测连通;可切 deepseek-v4-pro 提升质量)
```

**已实测的 API 细节(重要,直接照抄可用)**:

- 智谱视觉:`POST https://open.bigmodel.cn/api/paas/v4/chat/completions`,头 `Authorization: Bearer {ZHIPU_API_KEY}`,模型 `glm-4v-flash`,图片用 `content` 数组里的 `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}`。实测:16×16 测试图正常返回描述。
- 百智云文本:`POST https://ai-api-gateway.app.baizhi.cloud/api/anthropic/v1/messages`,头 `x-api-key: {BAIZHI_API_KEY}` + `anthropic-version: 2023-06-01`。⚠️ 响应 `content` 是数组,可能含 `thinking` 块,**必须取 `type:"text"` 的块拼接**。可用模型:`glm-5.3-flash`(默认)、`deepseek-v4-pro`、`gpt-5.6-sol` 等(实测 `/v1/models` 返回)。
- 密钥:已存在项目 `.env`(`ZHIPU_API_KEY`、`BAIZHI_BASE_URL`、`BAIZHI_API_KEY`、`BAIZHI_BASE_URL`),`.gitignore` 已保护。

**记忆条目结构**:

```json
{
  "id": "mem-<uuid>",
  "type": "photo | text | video",
  "time": 1758123456789,
  "content": "用户的原始文字(或空)",
  "thumb": "data:image/jpeg;base64,...",
  "ai": { "desc": "AI 的描述", "tags": ["跑步", "傍晚"], "emotion": "放松" }
}
```

**模型可切换原则**:所有模型调用收敛到 `lib/llm.ts` 的 `chat()` 与 `vision()` 两个函数。换供应商只改这一个文件 + `.env`——这是正式版换回 Claude 或其他模型的前提,不许在页面代码里直接发请求。

**部署**:Vercel(需在 Vercel 后台配置环境变量);本地 `npm run dev` 作为现场保底。成本:识别免费,写信每封 <0.1 元量级。

### 7.4 Assumptions(待验证假设)

以下假设没有经过验证,demo 现场的观察就是第一手证据:

| # | 假设 | 验证方式(demo 现场) |
|---|---|---|
| A1 | 用户愿意把真实生活素材交给 AI | 现场观众是否愿意用自己手机的照片试 |
| A2 | "发现"带来的惊喜感 > 隐私冒犯感 | 观众看到"发现"时的第一反应是 wow 还是皱眉 |
| A3 | 打动评委靠信件质量,不靠功能数量 | 对比:观众夸"信写得好"还是问"还有什么功能" |
| A4 | 每天+每周的节奏成立(季/年延后是用户决策,已确认) | 观众是否问"季度信呢" |
| A5 | 评委在国内时 vercel.app 可能不稳 | 已备本地保底,不赌 |
| A6 | 百智云是第三方中转,稳定性未知 | 仅 demo 使用;正式版需直连供应商(隐私硬要求) |
| A7 | localStorage 单设备够用 | 换设备丢数据是已知限制,可接受 |
